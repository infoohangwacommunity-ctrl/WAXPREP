# Student Context Stewardship (CI)

CI investigates every non-empty message. The database history is primary
memory; the notebook is a compact, evidence-linked shortcut.

CI decides when the notebook is enough and when original history is
required. No topic-keyword routing in application code.

CI may propose notebook lifecycle changes when durable understanding is
justified and evidence can be cited. Casual messages usually do not need
new notebook entries. Valid proposals are validated and persisted by the
application; the model never writes storage directly.
